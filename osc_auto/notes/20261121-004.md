# Docker inventory and SBOM

Objective: provide local container management and package inventory for OP02 and SA04.

Scope and decisions: Docker CLI uses the existing fixed local daemon and bounded execution; container IDs are validated and actions are allowlisted. Active container Debian and Alpine package databases are read through Docker copy without executing commands inside containers. Agent sends signed complete snapshots every five minutes while OPS is enabled. Image update status remains unknown until registry digest comparison exists. Unsupported package stores have an explicit status. Container-specific failures and oversized package inventories retain the overall snapshot, with `unavailable` or `too_large` status; oversized aggregate snapshots discard the largest package inventories explicitly until within the limit.

Outcome: added container and image list/inspect, start/stop and conservative prune operations; integrated signed inventory and Docker OPS actions. Docker access depends on the local service account's permissions and running daemon. Package inventory does not cover other package formats or language ecosystems.

Verification: `GOCACHE=/tmp/omnisight-go-cache go test ./...` passed; Windows cross-build passed. Live Docker integration and Windows execution not run.
