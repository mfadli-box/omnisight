# Manajemen kontainer dan SBOM OP02–SA04

Referensi: https://github.com/getarcaneapp/arcane

## Tujuan dan keputusan

Inventaris Docker dan aksi operator berjalan melalui agent lokal serta antrean OPS bertanda tangan. Snapshot dibatasi ukurannya, diautentikasi HMAC dan disimpan sesuai scope node. Pembacaan inventaris memerlukan OP02, pembacaan SBOM memerlukan SA04, start/stop memerlukan `can_update` OP02 dan prune memerlukan `can_delete` OP02. Prune menghapus seluruh kontainer berhenti pada node yang dipilih. UI memuat inventaris dan SBOM secara terpisah.

## Penerapan dan batasan

Terapkan `osc_base/migrations/010_container_inventory.sql` setelah migrasi 009, deploy REST dan UI, lalu deploy agent dengan `ops_enabled: true`, konfigurasi autentikasi/scope agent yang ada dan akses daemon Docker lokal. Snapshot dikumpulkan setiap lima menit dan dapat menjadi usang saat agent tidak tersedia. SBOM membaca database paket dpkg dan apk dari kontainer aktif; format paket dan ekosistem bahasa lainnya tidak dicakup. Status update image saat ini `unknown`: belum ada perbandingan digest registry. Operasi image tersedia pada executor lokal; UI/API aksi saat ini mencakup kontainer. Untuk rollback nonaktifkan OPS pada agent dan deploy versi sebelumnya; pertahankan tabel apabila data inventaris masih diperlukan.

## Verifikasi

Uji Go dan cross-build Windows lulus; `cargo test --lib` lulus; `npm run typecheck` lulus. Migrasi 009 dan 010 berhasil diterapkan pada skema PostgreSQL sementara yang minimal, lalu di-rollback. Pengujian end-to-end dengan daemon Docker dan database aplikasi belum dijalankan. Rincian per komponen berada dalam catatan `osc_auto/notes`, `osc_rest/notes`, dan `osc_site/notes` bertanggal 20261121-004.
