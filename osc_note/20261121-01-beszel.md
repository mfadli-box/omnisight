# Hub + Agent untuk CT01 dan OP02

OmniSight memakai pola Hub + Agent Beszel. Agent menjalankan pengukuran di node, REST menjadi hub, PostgreSQL menyimpan riwayat dan aturan alert, serta Valkey menyimpan heartbeat terbaru. [Referensi Beszel](https://github.com/henrygd/beszel)

| Pemilik | Hasil | Kriteria penerimaan |
| --- | --- | --- |
| ai-base | Migrasi `008_node_telemetry.sql` | Riwayat, aturan, dan status alert terisolasi per tenant dan area |
| ai-auto | Collector Linux dan Windows serta worker periodik | Host, S.M.A.R.T., dan statistik Docker dikirim dengan HMAC-SHA256 |
| ai-rest | Ingest, heartbeat, alert, dan API riwayat | Hanya node terdaftar boleh mengirim dan hanya pengguna berizin boleh membaca |
| ai-site | Panel riwayat pada CT01 dan OP02 | Grafik host, indikator S.M.A.R.T., dan TanStack Table untuk kontainer |

## Penerapan

1. Terapkan `osc_base/migrations/008_node_telemetry.sql` setelah skema inti dan kebijakan RLS. Deploy REST setelah migrasi berhasil.
2. Gunakan UUID huruf kecil dari `osc_agent_node.id`. Isi `AGENT_HEARTBEAT_SECRETS` dengan pasangan UUID dan rahasia unik per node. Isi `AGENT_TELEMETRY_SCOPES` dengan pemetaan berbentuk `{"<node UUID>":{"company_id":"<company UUID>","area_id":"<area UUID>"}}`. REST mencocokkan lokasi node di database dan mengambil store dari baris node tersebut.
3. Lewat ingress TLS, arahkan `POST /baas/v1/agents/telemetry` ke REST. Pertahankan byte body dan nilai header. Isi `hub_url`, `node_id`, `agent_secret`, dan `telemetry_enabled: true` pada agent. Mode heartbeat dan mode JSON sebelumnya tetap tersedia.
4. Gunakan identitas layanan dengan izin yang diperlukan untuk `smartctl` dan Docker lokal. Windows memakai PowerShell/CIM untuk counter tambahan. Load average Unix bernilai kosong pada Windows. Ketersediaan suhu dan S.M.A.R.T. bergantung sensor, perangkat, dan izin. Saat data tambahan tidak tersedia, agent masih mengirim metrik inti.
5. Pilih **Riwayat** pada baris node di CT01 atau OP02. UI menampilkan hingga 120 sampel terakhir dan memakai sampel terbaru untuk tabel S.M.A.R.T. serta kontainer.

## Kontrak dan perilaku

- Untuk ingest, tandatangani byte `"/baas/v1/agents/telemetry\n" + node_id + "\n" + timestamp + "\n" + body` dengan HMAC-SHA256. Kirim UUID pada `X-Agent-Id`, detik Unix pada `X-Timestamp`, dan hex huruf kecil pada `X-Signature`. Toleransi jam adalah 120 detik. PostgreSQL menyimpan timestamp terakhir untuk menolak replay dan sampel yang tiba di luar urutan.
- `GET /baas/v1/nodes/{id}/metrics` memakai sesi pengguna dan izin baca node CT01 atau OP02. Hasil diurutkan dari terbaru. `limit` menerima 1–200 dan `before` menerima waktu RFC 3339 eksklusif untuk pagination.
- Heartbeat telemetri memakai key Valkey yang sama dengan OP02 dengan TTL 900 detik. Jika Valkey gagal setelah transaksi PostgreSQL, riwayat dan alert tetap tersimpan. Pengiriman sampel baru berikutnya memperbarui cache ketika Valkey pulih.
- Administrator database provision aturan. `area_id` kosong menerapkan aturan ke seluruh area perusahaan. Aturan dipicu saat nilai mencapai atau melampaui ambang selama `duration_sec`. `load_avg` memakai nilai 1 menit, `disk_pct` memakai volume dengan persentase terisi tertinggi, dan `smart_failed` bernilai 1 jika ada disk gagal. Nilai kosong, nilai di bawah ambang, perubahan aturan, atau jeda sampel lebih dari 15 menit memulai evaluasi durasi yang baru.
- Hub menulis satu `AGENT_TELEMETRY_ALERT` ke `osc_activity_log` per episode. `webhook_url` disimpan untuk konfigurasi. Pengiriman notifikasi webhook berada di luar alur ini.
- Untuk rollback layanan, hentikan mode telemetri pada agent dan gunakan build REST/UI sebelumnya. Biarkan tabel tetap tersedia agar riwayat tersimpan.

## Verifikasi

- PGlite memverifikasi migrasi baru dan upgrade dari rantai lama, grant runtime, RLS tanpa konteks dan lintas company/area, serta durasi alert, deduplikasi, pemulihan, dan reset akibat jeda.
- Rust memverifikasi kompilasi dan HMAC, termasuk perubahan body, pemisahan endpoint, waktu kedaluwarsa, dan header duplikat.
- Smoke test HTTP dengan PostgreSQL 18 dan Valkey 8 sementara lulus untuk ingest, penolakan payload berubah dan replay, deduplikasi alert, TTL, riwayat dengan izin OP02 saja, serta penolakan akses lintas area dan setelah pencabutan izin.
- `go test ./...`, cross-build Windows amd64, `npm run typecheck`, dan build produksi UI melalui Docker lulus. Build UI langsung pada host terhalang pembatasan proses dan port sandbox.
- Uji pembacaan perangkat S.M.A.R.T. dan statistik Docker pada perangkat nyata, serta eksekusi CIM di Windows, belum dijalankan.
