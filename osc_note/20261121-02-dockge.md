# Docker Compose dan Web Terminal OP01–OP02

OP02 mengelola `compose.yaml` di direktori stack pada host agent. OP01 menjalankan diagnostik node dari Web Terminal dengan MFA. [Referensi Dockge](https://github.com/louislam/dockge)

| Bagian | Implementasi |
| --- | --- |
| ai-base | `009_compose_stacks.sql` menambah metadata stack, antrean operasi, dan log dengan RLS perusahaan, area, dan store. |
| ai-auto | Agent membaca dan menyimpan file host, menjalankan `up`, `down`, `pull`, `restart`, mengonversi `docker run` menjadi YAML, dan mengirim output bertanda tangan. |
| ai-rest | API stack dan terminal mengotorisasi target, memproses job bertanda tangan, mengirim SSE, dan mencatat audit. |
| ai-site | OP02 memiliki editor YAML dan penggantian `.env`, tombol aksi, serta output langsung. OP01 memiliki pemilih node, perintah, dan TOTP. |

## Penerapan

1. Terapkan `osc_base/migrations/009_compose_stacks.sql` setelah migrasi `008_node_telemetry.sql`, lalu deploy REST dan UI.
2. Daftarkan UUID node di `AGENT_HEARTBEAT_SECRETS` dan `AGENT_TELEMETRY_SCOPES`. Pemetaan scope memuat `company_id` dan `area_id`. REST memeriksa store serta status node dari database. Arahkan `/baas/v1/agents/ops/claim` dan `/baas/v1/agents/ops/event` ke REST melalui TLS. Pertahankan body dan header HMAC selama proxying.
3. Pasang Docker Compose pada node dan sediakan direktori stack absolut yang dimiliki identitas layanan agent. Set `ops_enabled: true` dan `compose_root` di YAML agent. Untuk terminal saja, biarkan `compose_root` kosong. Unit systemd bawaan menyediakan direktori tulis `/var/lib/omnisight-agent`. Di Windows, gunakan ACL direktori yang membatasi akses ke identitas layanan. Berikan akses daemon Docker lokal pada identitas agent untuk aksi Compose dan `docker ps`.
4. Berikan hak lihat, buat, dan ubah OP02 sesuai wewenang operator. Berikan hak buat OP01 kepada pengguna terminal. Di OP02, daftarkan stack pada node aktif lalu gunakan **Buka file host** untuk file yang sudah ada atau **Simpan file** untuk file baru. Di OP01, pilih node dan perintah, lalu masukkan TOTP ketika diminta.

## Kontrak dan batasan

- REST menyediakan `GET/POST /baas/v1/stacks`, `GET /baas/v1/stacks/{id}`, `POST /baas/v1/stacks/{id}/action`, serta `GET /baas/v1/stacks/{id}/logs/{job_id}`. Web Terminal memakai `GET /baas/v1/pam/terminal/nodes`, `POST /baas/v1/pam/terminal`, dan `GET /baas/v1/pam/terminal/{job_id}/logs`. Aksi diterima dengan HTTP 202 dan mengembalikan ID job. SSE mendukung penyambungan ulang dengan `Last-Event-ID`.
- Stack disimpan sebagai `<compose_root>/<stack_name>/compose.yaml`. Agent memvalidasi file yang akan disimpan melalui Docker Compose, mengganti file secara atomik per file, dan berusaha memulihkan `.env` apabila penggantian YAML gagal. Satu job aktif per node diserialkan oleh PostgreSQL. Operator yang mengubah file langsung perlu menghindari perubahan bersamaan dengan aksi dari UI. Status di database mencatat hasil aksi OmniSight.
- Compose mendukung image literal, port, environment, dan volume bernama. Allowlist agent membatasi konfigurasi yang dapat menyentuh host. Konverter menerima opsi umum `--name`, `--detach`, `--restart`, `--publish`, `--env`, `--volume` untuk volume bernama, serta `--label`. Argumen setelah image menjadi perintah kontainer.
- Editor `.env` menerima penggantian seluruh isi. Pilihan penggantian kosong mempertahankan file dengan isi kosong. Lindungi file host sebagai rahasia dan masukkan nilai sensitif melalui `.env`. Hub menyimpan salinan `.env` hasil simpan, payload job, dan output dengan AES-256-GCM menggunakan kunci yang diturunkan dari `MFA_ENCRYPTION_KEY`. Pertahankan kunci ketika melakukan deploy ulang.
- Polling agent membatasi replay dengan nonce pada klaim. HMAC event mencakup rute, ID agent, timestamp, dan body. REST memvalidasi sesi pengguna dan izin saat membaca log. Nomor urut mencegah pengiriman ulang output tercatat dua kali. Job dan output dapat dibersihkan saat agent kembali polling setelah 24 jam.
- Web Terminal menjalankan `uptime`, `df`, dan `docker ps`. REST memeriksa MFA aktif serta TOTP dari sesi yang sama dalam 15 menit saat antre, saat klaim, dan saat log dibaca. Audit mencatat perintah allowlist, node, aktor, penolakan MFA, dan hasil eksekusi tanpa OTP atau transkrip.
- Untuk rollback, nonaktifkan `ops_enabled` dan deploy ulang build sebelumnya. Pertahankan direktori stack serta tabel bila metadata dan audit masih dibutuhkan.

## Verifikasi

- PGlite memverifikasi migrasi, jalur yang dihasilkan, hak runtime, pemisahan tenant dan area, klaim, kedaluwarsa, serta pembersihan event.
- Uji Go mencakup validasi Compose, konversi, staging file dengan Docker Compose lokal, dan pengikatan HMAC. Agent juga dikompilasi untuk Windows amd64.
- Uji Rust dan typecheck UI lulus. Build produksi Next.js lulus melalui Docker.
- Uji integrasi lokal memakai PostgreSQL, Valkey, REST, agent Linux, dan Docker Compose. Uji mencakup penyimpanan, pembacaan, konversi, `pull`, `up`, `restart`, `down`, SSE dan penyambungan ulang lewat proxy Next.js, MFA/TOTP, audit penolakan serta hasil terminal, dan penolakan replay HMAC. Pengujian runtime agent dilakukan di Linux.
