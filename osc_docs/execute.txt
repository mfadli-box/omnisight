--- [SESI 0.4] Penyusunan Master Blueprint & Pembersihan Staging ---
Gunakan skill `ai-main` untuk membaca `osc_docs/audit-group-a.md`, `osc_docs/audit-group-b.md`, dan `osc_docs/audit-group-c.md`:

1. Susun cetak biru arsitektur terpadu di `osc_docs/reengineering.md` lengkap dengan diagram Mermaid yang menyatukan entitas induk `Asset`/`ManagedNode` dengan seluruh modul, pembagian Wave 1, Wave 2, dan Wave 3, serta spesifikasi lengkap berikut:

   - **Konfigurasi Multi-Company & HRIS ASMX Link**:
     - Setiap record `Company` memiliki `hris_login_url` (nullable) dan `hris_cache_ttl_hours` (default `72`).
     - Jika `hris_login_url` terisi (pola: `http://hris.check{\(U}&uPaswd={\)P}`), Rust (`osc_rest`) melakukan HTTP `GET` server-to-server (dengan allowlist domain/IP intranet HRIS anti-SSRF, batas respons 64 KB, dan sensor `uPaswd` pada log `tracing`).
     - Jika `hris_login_url` kosong atau user memilih opsi Company kosong (`""`), sistem menggunakan **Local Login** (`username` + `password` Argon2id).

   - **Parsing XML HRIS, Circuit Breaker & Cached Password Auto-Sync**:
     - Parse elemen `<string xmlns="...">` menggunakan parser XML aman (non-DTD) tanpa `.unwrap()`.
     - Jika berawalan `1|`: parse profil user, lakukan auto-provision/sync user lokal, hash password saat ini dengan `Argon2id` lalu simpan/perbarui ke `password_hash` beserta `last_hris_sync_at` (dilarang menyimpan password plaintext).
     - Jika berawalan `0|...|NONE`: tolak login `401 Unauthorized` tanpa fallback.
     - **Circuit Breaker & Offline Cache Fallback**: Terapkan Circuit Breaker pada client HRIS (jika gagal/timeout 5x dalam 30 detik, buka circuit selama 60 detik agar request tidak menumpuk). Saat upstream gangguan atau circuit terbuka, lakukan fallback verifikasi `Argon2id` terhadap `password_hash` lokal **hanya jika** selisih `last_hris_sync_at` masih dalam batas `hris_cache_ttl_hours` (catat di `ActivityLog` sebagai `LOGIN_HRIS_OFFLINE_CACHE`), atau kembalikan `502 Bad Gateway` (`HRIS_UPSTREAM_INVALID_RESPONSE`) jika cache tidak tersedia/kedaluwarsa.

   - **Optional TOTP MFA, Mandatory PAM MFA & Safe MFA Reset**:
     - Tabel `User` menyimpan `mfa_enabled` (default `false`), `mfa_secret_encrypted` (AES-256-GCM), `mfa_last_verified_step` (anti-replay), dan `mfa_backup_codes_hash` (Argon2id).
     - Jika `mfa_enabled == true`, `POST /api/v1/auth/login` mengembalikan `mfa_required: true` + `mfa_challenge_token` (JWT 5 menit dengan `scope: "mfa_pending"`). Sediakan endpoint `/api/v1/auth/mfa/setup`, `/enable`, `/verify` (rate-limit maks 5x gagal, toleransi ±1 step 30 detik), dan `/disable`.
     - **Mandatory MFA untuk PAM Bastion**: Endpoint `POST /api/v1/pam/sessions/authorize` wajib menolak akses (`403 MFA_REQUIRED_FOR_PAM`) jika `user.mfa_enabled == false`, serta mewajibkan step-up OTP jika verifikasi MFA terakhir lebih dari 15 menit.
     - **Akses Reset MFA (Human Error Recovery)**:
       1. *Self-Service*: User dapat memakai Backup Code sekali pakai di layar login untuk masuk dan otomatis me-reset `mfa_enabled = false`, atau meminta token reset MFA terverifikasi ke email terdaftar (`POST /api/v1/auth/mfa/reset-request` & `/reset-confirm` dengan pencabutan seluruh sesi aktif).
       2. *Admin-Assisted*: Endpoint `POST /api/v1/users/{id}/mfa/reset` bagi admin berizin untuk me-reset MFA user yang kehilangan perangkat + audit log `MFA_RESET`.

   - **Multi-Company Switcher, Menu Privilege & Strict Tenant Isolation**:
     - Tabel `UserCompanyAccess` (`user_id`, `company_id`, `role_id`, `is_default`, `is_active`) dan endpoint `POST /api/v1/auth/switch-company` untuk berpindah Company dan memperbarui `active_company_id` pada JWT (`HttpOnly` cookie di `osc_site` proxy), dilengkapi komponen **Company Switcher** di UI `osc_site`.
     - Tabel `MenuModule` & `CompanyMenuPrivilege` (`company_id`, `role_id`, `menu_id`, `can_view`, `can_create`, `can_update`, `can_delete`) serta endpoint `GET /api/v1/me/navigation` untuk merender sidebar dinamis di `osc_site`.
     - Seluruh tabel transaksi mengikat `company_id` dan difilter otomatis oleh middleware `RequestContext` di `osc_rest`.

   - **Day-2 Operational Foundations (Bootstrap, Enrollment, Notification & Retention)**:
     - **Idempotent Seeder (`osc_base`)**: Seeder wajib membuat akun awal `Global Super Admin` (dari `.env`) dan mengisi master registry `MenuModule` secara otomatis setelah migrasi.
     - **Agent Enrollment Flow**: Admin membuat one-time enrollment token terikat `company_id` di UI; agent Golang melakukan registrasi pertama kali ke `POST /api/v1/agents/enroll` untuk memperoleh `agent_id` dan `hmac_secret` secara otomatis.
     - **Centralized Notification Dispatcher**: Tabel `NotificationChannel` per Company (SMTP Email, Telegram, Webhook) yang dieksekusi secara asinkron oleh `osc_auto/flow_worker_agent` (untuk email reset MFA, alert metrik, downtime, dan SIEM).
     - **Data Retention Policy**: Kebijakan retensi/pembersihan terjadwal (30–90 hari) untuk tabel bervolume tinggi (`SystemMetricSnapshot`, `UptimeHeartbeat`) serta pengarsipan rekaman sesi PAM ke RustFS.

2. Hapus folder sementara `.rea_docs/` agar ruang disk bersih.
