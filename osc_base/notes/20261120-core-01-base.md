# Fondasi database PostgreSQL 18

## Menjalankan

Dari root repositori, gunakan koneksi administrator yang memiliki objek skema serta berwenang membuat dan memberikan role PostgreSQL.

```bash
psql "$DATABASE_ADMIN_URL" -v ON_ERROR_STOP=1 \
  -f osc_base/migrations/001_init_core.sql \
  -f osc_base/migrations/002_rls_policies.sql
```

Untuk database pengembangan atau demo, isi fixture setelah migrasi selesai.

```bash
psql "$DATABASE_ADMIN_URL" -v ON_ERROR_STOP=1 \
  -f osc_base/seeds/001_seed_demo.sql
```

Urutan ini berlaku untuk database baru dan database yang sudah menerapkan rantai historis sampai `007_report_archive.sql`. Pada instalasi lama, terapkan kedua migrasi dalam satu jendela pemeliharaan sebelum menjalankan versi API ini karena nama tabel dan kolom menu berubah. Untuk instalasi baru, jalankan file di atas secara eksplisit. Direktori migrasi juga berisi rantai historis, sehingga glob seluruh file akan mencampur dua jalur instalasi.

Compose membuat login `omnisight_app` saat volume baru diinisialisasi. Jika login runtime diprovisi setelah migrasi, berikan membership dengan `GRANT osc_app_runtime TO omnisight_app`.

## Cakupan dan keputusan

- Skema mencakup organisasi, identitas dan MFA, grant akses, katalog menu, serta tabel operasional dan arsip laporan. Foreign key komposit memvalidasi hubungan company–area–store, role–company, dan target–sesi PAM.
- `osc_user.company_id` menyimpan perusahaan asal opsional. Pengguna lintas perusahaan mendapat akses melalui `osc_user_access`. Grant menu per role berada di `osc_company_menu` dan tetap dibatasi entitlement perusahaan. Upgrade mempertahankan data dan relasi menu lama lewat penggantian nama tabel.
- RLS aktif dan dipaksa pada tabel operasional. Backend mengatur konteks di dalam transaksi dari company dan area yang sudah tervalidasi. Daftar area berupa UUID yang dipisahkan koma, dengan `{}` untuk daftar kosong yang sah. Baris dengan `area_id NULL` berlaku pada tingkat perusahaan. Baris operasional berflag aktif membutuhkan `is_active = true`, dan node juga memerlukan store aktif.
- Audit log hanya mendukung baca dan append dalam cakupan RLS. Trigger menolak perubahan, penghapusan, dan truncate. Ekspor node menyaring hash kredensial agent.
- Seed demo mengisi satu perusahaan IDM, area JKT dan SBY, dua store, satu SuperAdmin lokal dengan hash Argon2id, dan sepuluh menu. Seed dapat diulang tanpa menimpa hash atau grant yang sudah diprovisi.

## Hasil verifikasi

- PostgreSQL 17.5 melalui PGlite menjalankan instalasi baru, upgrade dari rangkaian migrasi historis, dan penerapan ulang migrasi serta seed. Jumlah dan isi fixture sesuai.
- Role runtime diuji terhadap akses lintas tenant dan area, konteks hilang atau cacat, company/area/store/baris nonaktif, serta baca dan tulis audit. Trigger audit diuji terhadap UPDATE, DELETE, dan TRUNCATE dengan role istimewa.
- Delapan pernyataan SQL yang berubah di API berhasil dipersiapkan di database uji. Query navigasi mengembalikan sepuluh menu. Verifier Argon2id cocok dengan kata sandi demo yang diminta.
- PostgreSQL 18 native dan alur API lengkap belum dijalankan. Akses Docker ditolak di lingkungan ini, dan `cargo check --offline` terhenti karena dependensi `redis` tidak tersedia di cache.
